# Phase 01 — Governance setup

> Depends on Phase 00 being confirmed by the human.

## What to do

1. Check whether the target project already has a `GOVERNANCE.md` (or an equivalent non-negotiable-foundation file). If it does, read it before changing anything — do not overwrite an existing governance file without understanding what it already commits the team to.
2. If none exists, draft one for the target project, using this skill's `references/non-negotiable-foundation.md` as the base content.
3. Adapt tone, severity framing, and scope emphasis to the target project's actual context — for example, a team under a regulated-sector accessibility obligation may want stronger language on Rule 1's consequences than a team with no such obligation. **Never remove, weaken, or make optional any of the four non-negotiable rules themselves** while adapting framing.
4. Keep the file brand-agnostic and in the target project's chosen documentation language (see the target project's own language policy, if one exists — otherwise default to English, and flag that a language policy decision is still open).

## 🛑 Stop point

Present the proposed `GOVERNANCE.md` to the human, in full, before writing it to the target project. Wait for explicit confirmation. Do not proceed to Phase 02 until the file is confirmed and written.
